# 네이버 예약 시간대 감시 매크로

모바일 네이버 예약(`m.booking.naver.com`)에서 **매진**이던 시간대가 **예약가능**으로
살아나는지 5분마다 자동으로 확인하고, 자리가 나면 **텔레그램으로 알림**을 보냅니다.

현재 감시 대상 (`config.json`):

| 상품 | 날짜 |
|---|---|
| `[48개월~10세] 거북이피자&제주바다블루레몬` | 2026-07-29(수), 2026-07-30(목) |
| `[성인쿠킹:10세~성인] 제주돼지치즈볼카츠&베이컨파스타` | 2026-07-29(수), 2026-07-30(목) |

동작 방식: GitHub Actions가 5분마다 실제 브라우저(Chromium)로 각 상품·날짜 페이지를 열어
시간대 버튼이 살아있는지(클릭 가능한지) 판별합니다. 직전 상태와 비교해 **새로 자리가 난 경우에만**
알림을 보내므로 같은 자리로 계속 스팸이 오지 않습니다.

## 알림은 어떻게 오나요?

1. **이메일 (기본 · 설정 불필요)** — 자리가 나면 이 저장소에 이슈가 자동으로 만들어지고,
   GitHub이 저장소 주인 이메일로 알림을 보냅니다. **아무 설정도 필요 없습니다.**
   - 혹시 메일이 안 오면 GitHub → **Settings → Notifications**, 그리고 저장소의 **Watch**가
     켜져 있는지 확인하세요(본인 저장소는 기본적으로 알림 대상입니다).
2. **텔레그램 (선택 · 즉시 푸시)** — 아래 절차로 Secret 2개만 넣으면 텔레그램 푸시도 함께 옵니다.

---

## (선택) 텔레그램 푸시 켜기

### 1) 텔레그램 봇 만들고 값 2개 얻기

1. 텔레그램에서 **@BotFather** 검색 → `/newbot` → 안내대로 이름 지정 → **봇 토큰**을 받습니다.
   (예: `8123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`)
2. 방금 만든 내 봇을 검색해 대화방을 열고 아무 메시지나 한 번 보냅니다(예: `안녕`).
3. **채팅 ID**를 확인합니다. 가장 쉬운 방법:
   - 텔레그램에서 **@userinfobot** 을 검색해 대화 → 알려주는 숫자 `Id`가 내 채팅 ID입니다.
   - (또는 브라우저에서 `https://api.telegram.org/bot<봇토큰>/getUpdates` 를 열면
     `"chat":{"id": ...}` 에 숫자가 보입니다.)

### 2) GitHub 저장소에 값 2개 등록

저장소 → **Settings → Secrets and variables → Actions → New repository secret** 에서 2개 추가:

| 이름 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 1단계에서 받은 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 1단계에서 받은 채팅 ID(숫자) |

끝입니다. 이제 자리가 나면 텔레그램 푸시도 함께 옵니다. 🎉

---

## 자동 실행에 대해

GitHub Actions의 **스케줄(cron) 실행은 기본 브랜치(main)에 있는 워크플로만 작동**합니다.
이 파일들은 `main`에 병합되어 있으므로 5분마다 자동으로 감시가 돌아갑니다.
(직접 포크/복사해 쓰는 경우에도 반드시 `main`에 두어야 자동 실행됩니다.)

---

## 먼저 잘 되는지 확인 (권장)

이 감시는 페이지 화면을 읽어 판별하므로, **처음 한 번은 디버그 모드로 확인**하는 걸 추천합니다.

1. 저장소 → **Actions → "네이버 예약 시간대 감시" → Run workflow**
2. `debug` 옵션을 **true**로 선택하고 실행
3. 실행이 끝나면 그 실행 페이지 하단 **Artifacts → `naver-debug-...`** 를 내려받으세요.
   - `*.png` : 그 시점 페이지 **전체 스크린샷** (매진/예약가능 눈으로 확인)
   - `*.json` : 판별 결과(`detection`)와 네이버가 실제로 호출한 API 응답
4. 실행 로그의 **Summary** 표에서 상품별 판별 결과(🟢 예약가능 / 🔴 매진)를 볼 수 있습니다.

스크린샷은 매진인데 매크로가 🟢로 잘못 읽거나 그 반대라면, `check.mjs`의
`detectInPage()` 안의 판별 규칙(`badWords`, `disabled` 클래스 패턴)만 조금 손보면 됩니다.
디버그 `*.json`에 캡처된 실제 API 응답이 튜닝의 근거가 됩니다.

> 참고: 이 매크로는 네이버 접속이 차단된 개발 환경에서 작성돼, 실제 네이버 페이지 대상 테스트는
> 위 디버그 실행으로 한 번 확인해 주세요. 로직(요일·URL·중복 알림 방지)은 검증되어 있습니다.

## 감시 대상/날짜 바꾸기

`config.json` 을 수정하면 됩니다. URL의 `bizes/<bizId>/items/<itemId>` 숫자와 날짜만 맞추면 돼요.

```jsonc
{
  "targets": [
    {
      "name": "표시할 이름",
      "bizId": "1282364",     // .../bizes/1282364/...
      "itemId": "7774984",    // .../items/7774984...
      "dates": ["2026-07-29", "2026-07-30"]   // 감시할 날짜(YYYY-MM-DD, 여러 개 가능)
    }
  ]
}
```

## 내 PC/서버에서 직접 돌리기 (선택)

```bash
cd scripts/naver-monitor
npm install
npx playwright install chromium

# 알림 없이 판별만 + 스크린샷 저장(debug/ 폴더)
npm run debug

# 실제 알림까지 (환경변수 필요)
TELEGRAM_BOT_TOKEN=xxx TELEGRAM_CHAT_ID=xxx node check.mjs
```

## 알림 끄기 / 종료

- 잠시 멈춤: **Actions** 탭 → 이 워크플로 → **⋯ → Disable workflow**
- 완전 종료: 워크플로 파일(`.github/workflows/naver-availability.yml`) 삭제
- 예약을 잡았다면 위 방법으로 꼭 꺼주세요(불필요한 실행 방지).

## 참고

- cron은 GitHub 부하에 따라 정확히 5분이 아니라 몇 분 늦을 수 있습니다.
- 공개 저장소의 스케줄 워크플로는 무료입니다.
- 저장소에 60일간 활동이 없으면 스케줄이 자동 중지됩니다(그 전에 예약은 끝날 날짜라 무관).
